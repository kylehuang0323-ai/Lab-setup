VM103 第一版封存 local-lvm 快照 NAS VZDump

先锁定一个可恢复的干净版本

适用于已经完成 Radeon 8060S、USB、RDP、本地直显和 PVE 自动启动验证的 Windows VM。当前 VM103 应先保存“正常账户登录已恢复”的 V1，再继续测试无密码登录、软件变更或每日自动回滚。

VM103 的 V1 定义：正常账户登录、GPU/USB/RDP/自动启动可用，尚未将新的无密码自动登录写入正式基线。封存日期为 2026-09-09。

1. 快照、备份和模板不是同一件事

保护层用途限制
本地快照几分钟内把当前 VM 回滚到已知状态依赖当前 PVE 和 local-lvm；宿主盘损坏时不能恢复
NAS VZDump 备份节点或虚拟磁盘损坏后的灾难恢复恢复时间长于快照；外置 VBIOS 需要单独保存
Golden Image / 模板部署 GMK004、GMK005 等新节点不能携带 GMK003 的 PCI、VBIOS、USB 和最终直显配置
不要把正在运行的 VM103 转换为模板。模板本身不能继续作为生产 Windows VM 自动启动。
数据范围：当前 C、D 分区位于同一块 VM 虚拟磁盘。回滚快照时，C 和 D 都会回到快照时刻；NAS 文件不在该虚拟磁盘中，不随 VM 快照回滚。

2. 封存前检查

在 VM103 的 Windows 管理员 PowerShell 中执行：

whoami

Get-CimInstance Win32_VideoController |
  Select-Object Name,DriverVersion,Status

Get-Volume -DriveLetter C,D |
  Format-Table DriveLetter,FileSystemLabel,Size,SizeRemaining -AutoSize

Get-Service QEMU-GA

Get-LocalUser |
  Format-Table Name,Enabled,PasswordRequired,PasswordLastSet -AutoSize

封存门

检查完成后正常关闭 Windows：

shutdown /s /t 0

PVE Shell 确认：

qm status 103

必须显示 status: stopped。不保存运行内存状态，不为 GPU 直通 VM 创建含 RAM 的快照。

3. 创建 VM103 第一版快照

PVE Shell

VM_ID=103
SNAPSHOT="clean-baseline-v1"

qm snapshot "$VM_ID" "$SNAPSHOT" \
  --description "GMK003 baseline v1 - normal login restored - GPU USB RDP verified - 2026-09-09"

qm listsnapshot "$VM_ID"

应看到 clean-baseline-v1。如果名称已经存在，不要覆盖或先删除，改用 clean-baseline-v1a，确认旧版本不再需要后再清理。

PVE Web

VM 103快照创建快照clean-baseline-v1
字段值
名称clean-baseline-v1
描述GMK003 baseline v1 - normal login restored - 2026-09-09
包含 RAM不勾选；VM 应处于 stopped

4. 同步保存 VM 配置与本机 VBIOS

快照不能替代外部配置归档。VM103 使用的 romfile 位于宿主机 /usr/share/kvm，需要单独保存。

VM_ID=103
NODE="$(hostname)"
BACKUP_DIR="/root/gmk003-backup/baseline-v1-20260909"
CONFIG_PATH="/etc/pve/nodes/${NODE}/qemu-server/${VM_ID}.conf"
ROM_PATH="/usr/share/kvm/gmk003-vbios-8060s.bin"

mkdir -p "$BACKUP_DIR"

qm config "$VM_ID" > "$BACKUP_DIR/${VM_ID}.conf.txt"
cp -a "$CONFIG_PATH" "$BACKUP_DIR/${VM_ID}.conf"
cp -a "$ROM_PATH" "$BACKUP_DIR/"

sha256sum "$BACKUP_DIR/gmk003-vbios-8060s.bin" \
  > "$BACKUP_DIR/gmk003-vbios-8060s.sha256"

ls -lh "$BACKUP_DIR"

必须同时看到：

103.conf
103.conf.txt
gmk003-vbios-8060s.bin
gmk003-vbios-8060s.sha256
其他节点要使用自己的 VM ID、节点目录和本机提取的 VBIOS。不要将 GMK003 的 ROM 作为 GMK004/005 默认文件。

5. 创建 NAS 第一版镜像备份

VM 103备份立即备份nas-pve-backup
选项设置
存储nas-pve-backup
模式Stop
压缩ZSTD
备注GMK003 baseline v1 - normal login restored - 2026-09-09

等待任务显示 TASK OK，然后检查：

pvesm list nas-pve-backup --vmid 103
该 VZDump 是 GMK003 节点专用恢复版本。虽然可以恢复到其他 PVE，但首次启动前必须删除旧的 hostpci、USB、VBIOS名称、vga: none、重复 MAC 和自动启动配置。

6. 封存后的冷启动验收

快照和 NAS 备份都完成后，关闭 PVE：

poweroff
  1. 等待主机完全断电30秒。
  2. 手动按 GMK003 电源键。
  3. 不要执行 qm start 103。
  4. PVE 等待30秒后应自动启动 VM103。
  5. 物理显示器进入 Windows 原账户登录界面。
  6. 检查 GPU、USB、RDP、D盘和 NAS。

V1 完成条件

7. 测试失败时回滚 V1

优先在 Windows 中正常关机：

shutdown /s /t 0

PVE 确认停止并回滚：

qm status 103
qm listsnapshot 103
qm rollback 103 clean-baseline-v1
qm status 103
回滚会删除快照之后 C、D盘中的改动。包括新账户、新软件、桌面文件和后来下载到 D 盘的 Ollama 模型。永久文件应放 NAS。

回滚后不要立即反复启动 GPU VM，关闭宿主机：

poweroff

等待30秒后手动开机，让 PVE 自动启动 VM103。这样可以降低 Radeon 8060S reset bug 导致黑屏或 Code 43 的概率。

8. 基线版本命名与升级

版本建议状态
clean-baseline-v1正常账户登录恢复，GPU/USB/RDP/自动启动稳定
clean-baseline-v2I-LAB软件、Ollama路径和标准模型完成
clean-baseline-v3登录策略和每日还原机制完成最终验收

创建新版本时保留上一版，至少完成一次冷启动和一次手动回滚测试后，才考虑删除更旧快照：

qm snapshot 103 clean-baseline-v2 \
  --description "GMK003 I-LAB software baseline v2 - YYYY-MM-DD"

qm listsnapshot 103

删除快照属于不可逆操作，执行前先确认 NAS 中存在对应版本备份：

qm delsnapshot 103 clean-baseline-v1

9. 跨节点 Image 的正确边界

VM103 的本地快照只能服务 VM103。GMK004/005 不能直接使用该快照。

可以进入通用 Image必须逐台重新配置
Windows、VirtIO、QEMU-GA、软件、基础策略GPU和Audio PCI地址
Ollama程序和标准模型本机 VBIOS 和 SHA256
RDP、NAS脚本、桌面快捷方式hostpci、USB、x-vga、vga:none
经过 Sysprep 的系统基线PVE管理IP、VM ID、MAC、Windows名称和IP

后续制作通用 Golden Image 时，应恢复到一个临时 VM，去除节点专属硬件配置，再执行 Sysprep 和 NAS 备份。生产 VM103 保持可运行，不转换为模板。

10. 自动回滚的启用边界

V1 阶段只建立人工恢复点，不立即启用定时回滚。自动回滚应等软件、模型、登录方式和 NAS 持久化全部验收后再配置。

Windows正常关机回滚本机基线VM保持停止PVE关机下次冷启动
不要照搬“回滚后立即 qm start”的普通虚拟机方案。Radeon 8060S 直通节点应通过整机冷启动重新初始化 GPU。

多节点最终可通过 Ansible + Cron 错峰执行，但每个 VM 必须拥有自己的基线快照，且脚本中的 VM ID、快照名称和执行时间必须来自节点清单。
