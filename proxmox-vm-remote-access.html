Proxmox VE 9.2 Windows 11 Pro / Enterprise MIX 管理机

从管理机稳定访问 Windows VM

本模块用于配置和排查 Proxmox 中 Windows VM 的远程访问。先用 noVNC 完成安装和救援，再配置 QEMU Guest Agent 与 RDP；GPU 直通导致虚拟控制台无画面后，RDP 是主要恢复通道。

MIX 管理机→PVE Web / noVNC→Windows VM→RDP 日常访问
停止条件：RDP 尚未从 MIX 实际登录成功时，不要配置 vga: none、不要屏蔽 amdgpu、不要开始 GPU 直通。

1. 开始前检查

对象示例要求
PVE 管理地址192.168.0.103:8006从 MIX 可访问；每台宿主机地址唯一
Windows VM 地址192.168.0.148与 PVE 地址不同；通过 DHCP 或批准的固定地址获得
VM 配置vmbr0 + VirtIO网卡未断开，VLAN 与现场网络一致
Windows 版本Pro / EnterpriseWindows Home 不能作为 Microsoft RDP 主机
登录账户本地或组织账户必须设置密码；空密码账户不能远程登录

2. noVNC：安装和救援入口

noVNC 通过浏览器访问 VM 的虚拟显示器，不依赖 Windows 网络。首次安装、网卡驱动故障或 RDP 不可用时优先使用。

PVE Web UI选择 Windows VM控制台

noVNC 无画面时

  1. 确认 VM 状态为 running。
  2. 在“硬件”中确认“显示”仍为 Default 或其他虚拟显示设备。
  3. 如果已设置 vga: none，GPU 直通模式下 noVNC 无画面属于预期行为，应改用物理显示器或 RDP。
qm status VM_ID
qm config VM_ID | grep -E '^(vga|hostpci|net)'

3. 安装 VirtIO 与 QEMU Guest Agent

在 PVE 的 VM“硬件”页面挂载 virtio-win.iso，然后在 Windows 文件资源管理器中打开该光盘。

推荐安装方式

virtio-win-guest-tools.exe

右键选择“以管理员身份运行”。如果需要分别安装：

guest-agent\qemu-ga-x86_64.msi
NetKVM\w11\amd64       # VirtIO 网卡
vioserial\w11\amd64    # PCI Simple Communications Controller
VM选项QEMU Guest Agent启用

Windows 内验证

Get-Service -Name QEMU-GA
Get-NetAdapter

应看到 QEMU-GA 为 Running，网卡为 Red Hat VirtIO Ethernet Adapter 且状态为 Up。

PVE Shell 验证

qm agent VM_ID ping
qm guest cmd VM_ID get-osinfo
qm guest cmd VM_ID network-get-interfaces
如果找不到 QEMU-GA 服务：说明 Guest Agent 尚未安装，而不是 PowerShell 命令错误。安装 MSI 后将 Windows 完整关机，再从 PVE 启动。

4. 配置并验证 Windows 网络

PVE 网卡设置

VM硬件网络设备 net0编辑
字段建议值
模型VirtIO (paravirtualized)
桥接vmbr0
VLAN Tag留空，除非网络管理员指定
断开连接不勾选
MAC 地址保持不变，避免 DHCP Reservation 失效
防火墙按现场策略；排障时可暂时取消 VM 网卡防火墙

Windows PowerShell 检查

Get-NetAdapter | Format-Table Name,InterfaceDescription,Status,MacAddress,LinkSpeed
Get-NetIPConfiguration
ipconfig /all

如果地址为 169.254.x.x，网卡已加载但未获得 DHCP 地址：

Set-NetIPInterface -InterfaceAlias "Ethernet" -Dhcp Enabled
Set-DnsClientServerAddress -InterfaceAlias "Ethernet" -ResetServerAddresses
ipconfig /release
ipconfig /renew

基础连通测试

ping 实际网关IP
ping NAS_IP
ping PVE_IP
Resolve-DnsName download.microsoft.com

5. 在 Windows VM 启用 RDP

版本要求：Windows 11 Pro、Enterprise 或 Education 可以作为 RDP 主机；Windows 11 Home 不支持接收入站 RDP。

图形界面

设置系统远程桌面开启

管理员 PowerShell 配置

Set-ItemProperty `
  -Path 'HKLM:\SYSTEM\CurrentControlSet\Control\Terminal Server' `
  -Name fDenyTSConnections `
  -Value 0

Set-Service -Name TermService -StartupType Automatic
Start-Service -Name TermService

Enable-NetFirewallRule -Name 'RemoteDesktop-UserMode-In-TCP'
Enable-NetFirewallRule -Name 'RemoteDesktop-UserMode-In-UDP'

Set-NetConnectionProfile `
  -InterfaceAlias 'Ethernet' `
  -NetworkCategory Private

允许 Ping 以便排障

New-NetFirewallRule `
  -DisplayName 'Allow ICMPv4 Echo for Lab' `
  -Direction Inbound `
  -Protocol ICMPv4 `
  -IcmpType 8 `
  -Action Allow `
  -Profile Any

确认服务监听

Get-ComputerInfo | Select-Object WindowsProductName,WindowsEditionId
Get-Service -Name TermService
Get-NetTCPConnection -LocalPort 3389 -State Listen
Test-NetConnection localhost -Port 3389

登录账户必须有密码。查看当前账户：

whoami
Get-LocalUser

6. 从 MIX 管理机验证

先记录 Windows VM 的实际 IPv4 地址，不要误用 PVE 管理地址。

MIX PowerShell

ping WINDOWS_VM_IP
Test-NetConnection WINDOWS_VM_IP -Port 3389

只要结果为 TcpTestSucceeded : True，就可以启动远程桌面：

mstsc
结果判断
Ping 成功，3389 为 True网络与 RDP 均正常
Ping 失败，3389 为 True仅 ICMP 被拦截，RDP 仍可使用
VM 本机 3389 为 True，MIX 为 False检查 Windows/PVE 防火墙、VLAN 或网络客户端隔离
VM 本机 3389 为 False检查 Windows 版本、TermService 和防火墙规则
端口通但认证失败检查用户名、密码和 Remote Desktop Users 权限

7. GPU 直通前后的访问策略

首次添加 GPU 时

  • 保留虚拟显示设备，让 noVNC 继续可用。
  • 先不要添加 x-vga=1，不要设置 vga: none。
  • 通过 noVNC 或 RDP 安装 AMD 官方驱动，确认设备管理器无 Code 43。

切换为本地直显前

  1. 通过 RDP 实际登录成功。
  2. 将 VM 备份到 NAS，备注为 pre-GPU-passthrough。
  3. 备份 /etc/pve/qemu-server/<VM_ID>.conf。
  4. 设置 x-vga=1 和 vga: none 后，预期 noVNC 不再显示桌面。
最终访问组合：PVE Web/SSH 管理宿主机；物理 HDMI/DP 和 RDP 访问 Windows VM；noVNC 仅在保留虚拟显示器时可用。

8. 常见故障排查

VM 有互联网，但 MIX 无法 Ping 或 RDP

这通常是入站防火墙、RDP 服务、PVE VM 防火墙或网络客户端隔离问题。分别测试 VM 本机和 MIX 的 3389 端口，不要只依赖 Ping。

# Windows VM
Test-NetConnection localhost -Port 3389

# MIX
Test-NetConnection WINDOWS_VM_IP -Port 3389
TermService 显示 Running，但 3389 没有监听

如果 Get-Service TermService 显示 Running，但 Get-NetTCPConnection 报“找不到匹配对象”，且本机 3389 测试失败，表示服务进程存在，但 RDP 监听器尚未启用。这不是 Get-NetTCPConnection 命令本身出错。

先确认 Windows 版本。WindowsEditionId 为 Professional 或 Enterprise 时支持作为 RDP 主机；某些 Windows 11 系统仍可能在 WindowsProductName 中显示 Windows 10，不应仅凭这个名称判断版本。

Get-ComputerInfo |
  Select-Object WindowsProductName,WindowsEditionId

Get-Service -Name TermService
Get-ItemProperty `
  -Path 'HKLM:\SYSTEM\CurrentControlSet\Control\Terminal Server' `
  -Name fDenyTSConnections

在 Windows VM 的管理员 PowerShell中启用 RDP、开放语言无关的内置防火墙规则并重启服务：

Set-ItemProperty `
  -Path 'HKLM:\SYSTEM\CurrentControlSet\Control\Terminal Server' `
  -Name fDenyTSConnections `
  -Value 0

Enable-NetFirewallRule -Name 'RemoteDesktop-UserMode-In-TCP'
Enable-NetFirewallRule -Name 'RemoteDesktop-UserMode-In-UDP'

Set-Service -Name TermService -StartupType Automatic
Restart-Service -Name TermService -Force

立即执行四项验证：

Get-ItemProperty `
  -Path 'HKLM:\SYSTEM\CurrentControlSet\Control\Terminal Server' `
  -Name fDenyTSConnections

qwinsta
Get-NetTCPConnection -LocalPort 3389 -State Listen
Test-NetConnection localhost -Port 3389

成功时应看到 fDenyTSConnections : 0、qwinsta 中存在 rdp-tcp，并且 TcpTestSucceeded : True。

仍未监听：通过 noVNC 在管理员 PowerShell 执行 shutdown /r /t 0 完整重启 Windows VM。不要在远程桌面连接中途重启 TermService。

VM 重启后先在 VM 本机复测，再从 MIX 测试：

# Windows VM
Get-NetTCPConnection -LocalPort 3389 -State Listen
Test-NetConnection localhost -Port 3389

# MIX 管理机
Test-NetConnection WINDOWS_VM_IP -Port 3389
验证结果下一步
VM 本机为 True，MIX 也为 True运行 mstsc 登录 VM
VM 本机为 True，MIX 为 False检查 PVE 的 VM 网卡防火墙、VLAN、MIX 路由和网络客户端隔离
VM 本机仍为 False检查组策略、Windows 组件状态或组织安全策略；不要继续 GPU 直通
VM硬件网络设备 net0编辑排障时暂时取消“防火墙”

不要删除虚拟网卡，也不要重新生成 MAC 地址。排障完成后，按组织安全策略恢复 PVE 防火墙设置。

设备管理器出现 PCI Simple Communications Controller 感叹号

从 VirtIO 光盘安装 vioserial\w11\amd64；硬件 ID 通常包含 VEN_1AF4。

QEMU-GA 服务不存在

运行 guest-agent\qemu-ga-x86_64.msi 或根目录的 virtio-win-guest-tools.exe，然后完整关机再启动。

Windows 网卡显示 169.254.x.x

确认 PVE 网卡桥接到 vmbr0、未断开，并检查现场 DHCP。不要随意占用一个看似空闲的固定 IP。

GPU 直通后 noVNC 黑屏

如果配置中存在 vga: none，这是正常现象。检查物理显示器和 RDP；如两者均不可用，通过 PVE Web/SSH 回滚 GPU 直通配置。

PVE 侧只读诊断

qm status VM_ID
qm config VM_ID
ip -br address show vmbr0
bridge link
pvesh get /nodes/$(hostname)/qemu/VM_ID/agent/network-get-interfaces 2>/dev/null

9. 安全与日常运维

  • 不要将 TCP 3389 直接暴露到互联网；只允许可信管理网、VPN 或批准的跳板机访问。
  • 使用有密码的专用管理账户，并按最小权限授予 Remote Desktop Users。
  • 保留 Windows 防火墙；排障时临时放宽规则，完成后恢复现场安全策略。
  • 通过 DHCP Reservation 或批准的静态地址稳定 VM IP，避免 RDP 收藏地址失效。
  • 在 NAS 保存 VM 备份；快照不等同于长期备份。
  • 记录 PVE IP、VM IP、MAC、VM ID、Windows 版本和 VirtIO 版本。
凭据要求：不要在脚本、HTML 文档或共享目录中保存明文密码。生产环境应遵循组织的账户、MFA、网络分段和审计策略。
