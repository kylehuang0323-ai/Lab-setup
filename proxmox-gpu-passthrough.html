0. 先理解目标、风险和停止条件

最重要警告：安装 Proxmox 会清空所选内部磁盘

如果现在的 Windows C盘和保留用 D盘位于同一块 NVMe 上，安装 Proxmox 到该 NVMe 后，C盘、D盘、冰点还原配置都可能被删除。NAS 中的数据不会因本机重装自动删除，但仍要确认同步已完成。

没有完成数据备份、没有确认目标磁盘时，禁止点击安装器最后的 Install。

  ↓ 延迟约30秒

  ↓ 接管整块GPU

顺序不可跳过：先保证 Web/SSH/RDP 三条恢复通道，再屏蔽宿主机显卡。每个阶段只有在“验收门”全部通过后才能继续。

2. 设置 EVO-X2 BIOS/UEFI

开机看到 GMKtec 标志时，通常反复按 Delete 进入 BIOS；一次性启动菜单常见为 F7。具体按键随 BIOS 版本可能不同。

  1. 先拍照：进入 BIOS 后，用手机拍摄当前关键页面，特别是 Boot、Security、AMD CBS/CPU、UMA。
  2. 启用虚拟化：找到 SVM / AMD Virtualization，设为 Enabled。
  3. 启用 IOMMU：找到 IOMMU / AMD-Vi，设为 Enabled。
  4. 启动模式：UEFI Boot = Enabled；CSM / Legacy Boot = Disabled（如有）。
  5. PCI 空间：Above 4G Decoding = Enabled（如有）；Re-Size BAR 保持默认或 Enabled。
  6. 固定 UMA/VRAM：不要动态自动调整。首次验证建议 16 GB 或 32 GB；运行较大本地模型时再评估 32/64 GB。
  7. 保存退出：按界面提示 Save Changes and Exit。
实际 BIOS 版本实际 UMA修改日期
菜单名称找不到时不要随便改相似项目。先拍照并停止；不同固件版本的位置可能不同。

验收门 2

3. 从现有U盘安装 Proxmox VE 9.2-1

本章包含擦盘操作。务必核对目标 NVMe 的型号和容量，不要仅凭“Disk 0”判断。连接了额外数据盘时，最好先物理断开，避免选错。
  1. 接线：关闭 EVO-X2，插入 Proxmox 启动U盘、网线、显示器、键盘；保留管理员电脑在同一可管理网络。
  2. 从U盘启动：开机反复按一次性启动菜单键（常见 F7），选择带 UEFI 前缀的U盘。不要选内部 NVMe。
  3. 选择安装方式：在 Proxmox 菜单选择 Install Proxmox VE (Graphical)。如果图形界面异常，可再使用 Terminal UI，但首次优先 Graphical。
  4. 阅读并接受 EULA：选择 I agree。
  5. 选择 Target Harddisk：按型号/容量确认内部目标 NVMe。单 NVMe 首次部署可保持默认 ext4 + LVM-thin；不要不理解就修改 Advanced Options。
  6. Country / Time zone / Keyboard：按实际地点选择。中国大陆一般 Time zone 为 Asia/Shanghai；键盘按实物布局选择。
  7. 管理员凭据：设置强 root 密码并填写真实管理员邮箱。密码保存在受控密码库，不贴在机身上。
  8. Management Network：选择插着网线的网卡；填写前章确认的 FQDN、固定 IP/CIDR、Gateway、DNS。每项都核对。
  9. Summary 最后检查：重点确认 Target Disk、Hostname、IP、Gateway。确认备份完成后才点击 Install。
  10. 重启：安装完成后选择 Reboot。在设备重新启动前拔出安装U盘，避免再次进入安装器。
正常现象：重启后本机控制台会显示访问地址，例如 https://192.168.x.x:8006/ 和登录提示。先不要配置 GPU 直通。

4.3 配置官方软件仓库并更新

先判断订阅类型：有有效 Proxmox 企业订阅时保留 Enterprise repository，不要执行下面的无订阅换源命令。没有企业订阅时，使用 Proxmox 官方 No-Subscription 仓库。

方法一（推荐新手）：在 Web UI 中配置：

Datacenter → ws-001 → Updates → Repositories
→ 禁用无授权的 enterprise 项
→ Add → No-Subscription（PVE）

方法二（完整 Shell 命令）：仅在没有企业订阅、且尚未通过 Web UI 添加 No-Subscription 仓库时执行。整段复制到 PVE Shell；脚本会先备份源文件，再禁用 PVE/Ceph 企业源并添加 PVE 9 的官方免费源。

set -e

# 1. 备份当前 APT 软件源
BACKUP_DIR="/root/apt-sources-backup-$(date +%Y%m%d-%H%M%S)"
mkdir -p "$BACKUP_DIR"
[ ! -f /etc/apt/sources.list ] || cp -a /etc/apt/sources.list "$BACKUP_DIR/"
cp -a /etc/apt/sources.list.d "$BACKUP_DIR/"
echo "APT sources backup: $BACKUP_DIR"

# 2. 禁用无订阅环境无法访问的 Enterprise 源
if [ -f /etc/apt/sources.list.d/pve-enterprise.sources ]; then
  mv /etc/apt/sources.list.d/pve-enterprise.sources \
     /etc/apt/sources.list.d/pve-enterprise.sources.disabled
fi

if [ -f /etc/apt/sources.list.d/pve-enterprise.list ]; then
  mv /etc/apt/sources.list.d/pve-enterprise.list \
     /etc/apt/sources.list.d/pve-enterprise.list.disabled
fi

# 当前部署不使用 Ceph；禁用安装器预置的 Ceph Enterprise 源
if [ -f /etc/apt/sources.list.d/ceph.sources ]; then
  mv /etc/apt/sources.list.d/ceph.sources \
     /etc/apt/sources.list.d/ceph.sources.disabled
fi

if [ -f /etc/apt/sources.list.d/ceph.list ]; then
  mv /etc/apt/sources.list.d/ceph.list \
     /etc/apt/sources.list.d/ceph.list.disabled
fi

# 3. 添加 Proxmox VE 9 / Debian 13 (trixie) 官方 No-Subscription 源
cat > /etc/apt/sources.list.d/pve-no-subscription.list <<'EOF'
deb http://download.proxmox.com/debian/pve trixie pve-no-subscription
EOF

# 4. 显示最终启用的仓库，确认不再包含 enterprise.proxmox.com
grep -RhsE '^(deb |URIs:|Suites:|Components:)' \
  /etc/apt/sources.list /etc/apt/sources.list.d/ 2>/dev/null || true

# 5. 刷新索引并完整升级
apt clean
apt update
apt full-upgrade -y
成功标准：apt update 结束时没有 401 Unauthorized、签名错误或 DNS 错误，且 apt full-upgrade 正常完成。升级期间不要关闭电源。

升级完成后先查看版本，再重启：

pveversion -v
uname -r
reboot

重启后重新登录 Web UI 或 SSH，确认管理网络和新内核：

hostname
ip -br addr
ip route
pveversion -v
uname -r
如果更新仍然报错，展开运行诊断命令

仍出现 401 Unauthorized

grep -Rni "enterprise.proxmox.com" \
  /etc/apt/sources.list /etc/apt/sources.list.d/ 2>/dev/null || true

出现 Temporary failure resolving / Could not resolve

ip route
ping -c 4 实际网关IP
getent hosts download.proxmox.com
cat /etc/resolv.conf

出现证书尚未生效或已过期

timedatectl status

不要通过关闭签名验证、使用不可信镜像或执行来源不明的一键脚本绕过错误。

6. 用虚拟显示器安装 Windows、VirtIO 与远程通道

  1. 打开控制台：选择 VM101 → Console，开始 Windows 安装。此时画面来自 Proxmox 虚拟显示器。
  2. 看不到硬盘时加载驱动：将 VirtIO ISO 挂载为第二张光盘；在 Windows 的“你想将 Windows 安装在哪里？”选择“加载驱动程序”，浏览 VirtIO 光盘中的 vioscsi\w11\amd64。实际控制器不同才评估 viostor。
  3. 完成 Windows 安装：按组织账户和安全策略配置，不通过脚本绕过企业要求。
  4. 安装 VirtIO 工具：在 VirtIO 光盘运行 virtio-win-gt-x64.msi；确认网卡、存储等驱动完成。
  5. 安装 QEMU Guest Agent：可从 VirtIO 光盘安装 guest-agent\qemu-ga-x86_64.msi；在 Windows 服务中确认 QEMU Guest Agent 正在运行。
  6. 完成 Windows Update：重启并持续更新，直到没有待安装的关键更新。
  7. 建立远程通道：Windows Pro/Enterprise 启用“设置 → 系统 → 远程桌面”；记录 VM IP，并从管理员电脑测试 RDP。
  8. 记录网络：为 VM 使用网络管理员批准的固定 IP 或 DHCP Reservation，不要与 PVE 管理 IP 重复。

在 Proxmox Shell 备份 VM 配置。使用节点完整路径，避免部分环境中 /etc/pve/qemu-server 快捷路径不存在：

VM_ID=101
NODE="$(hostname)"
BACKUP_DIR="/root/ws001-backup/vm${VM_ID}-pre-gpu"
CONFIG_PATH="/etc/pve/nodes/${NODE}/qemu-server/${VM_ID}.conf"

mkdir -p "$BACKUP_DIR"
qm config "$VM_ID" > "$BACKUP_DIR/${VM_ID}.conf.txt"

if [ ! -f "$CONFIG_PATH" ]; then
  echo "VM config not found: $CONFIG_PATH"
  find /etc/pve/nodes -path "*/qemu-server/${VM_ID}.conf" -print
  exit 1
fi

cp -a "$CONFIG_PATH" "$BACKUP_DIR/${VM_ID}.conf"
ls -lh "$BACKUP_DIR"
输入注意：cp -a 中必须使用英文半角短横线，并在 cp、-a、源路径和目标路径之间保留空格。不要输入 cp –a 或 cp -a/etc/...。

成功时目录中会同时出现 101.conf 和 101.conf.txt；前者是原始 PVE 配置文件，后者是 qm config 的可读输出。

验收门 6

7. 重建“C盘可恢复、D盘保留、NAS共享”的数据结构

推荐结构：不要只在同一个虚拟磁盘里划 C/D 两个分区。用两个独立虚拟磁盘，未来恢复系统盘时才不容易误覆盖 D盘。
VM101
├─ scsi0 → Windows C盘（系统、驱动、软件）
├─ scsi1 → Windows D盘（模型、项目、缓存，持久）
└─ NAS    → 重要成果、团队共享、正式备份

7.1 添加独立数据盘

  1. 关闭 VM101。
  2. 在 Web UI 选择 VM101 → Hardware → Add → Hard Disk。
  3. Bus/Device 选择 SCSI，应生成 scsi1；选择容量和存储池。
  4. 启动 Windows，打开“磁盘管理”；初始化新磁盘为 GPT，创建卷并分配盘符 D:。
  5. 在磁盘卷标中明确写为 VM101-DATA。

7.2 连接 NAS

在 Windows VM 内按组织批准方式映射网络驱动器。不要把 NAS 管理员凭据保存在所有共享用户都可读取的位置。建议按用户/项目授权，并启用 NAS 版本历史或备份。

关于自动还原：本文先完成稳定直通，不在此阶段配置“每次重启恢复 C盘”。Proxmox 快照不应被当成长期备份。后续如需共享工作站自动还原，应单独评估 Windows 写入过滤、模板克隆或受控恢复流程。

8. 识别 WS-001 自己的 PCI 地址和 IOMMU 分组

在 PVE Shell/SSH 中执行。不要抄其他设备的 c5:00.x，每台机器都可能不同。

lspci -nn | grep -Ei 'VGA|Display|Audio|USB|Encryption|Crypto'
lspci -nnk -d 1002:1586
lspci -nnk -d 1002:1640

Strix Halo 8060S 常见 ID：

GPU：       1002:1586
GPU Audio： 1002:1640

查看 IOMMU 分组：

for g in /sys/kernel/iommu_groups/*; do
  echo "IOMMU GROUP ${g##*/}"
  for d in "$g"/devices/*; do
    lspci -nns "${d##*/}"
  done
done
项目WS-001 实际值
GPU PCI 地址（1002:1586）
GPU Audio PCI 地址（1002:1640）
GPU IOMMU Group
可选 USB Controller
管理网卡 PCI 地址（严禁直通）
不要为了“让它能启动”直接开启 ACS override 或 unsafe interrupts；这会削弱隔离。IOMMU 分组不清楚时停止并保留命令输出。

9. 在屏蔽 amdgpu 前，提取 WS-001 自己的 8060S VBIOS

禁止：不要直接使用网上ROM或另一台 EVO-X2 的 ROM 作为生产基线。VFCT 不存在或无法得到 1002:1586 时，本阶段停止。

9.1 确认 VFCT 并安装编译器

apt update
apt install -y build-essential
ls -l /sys/firmware/acpi/tables/VFCT

若最后一条显示文件存在，继续；不存在则停止并查阅原 Markdown 指南的 VBIOS 备选路径。

9.2 创建提取程序

执行 nano /root/vbios.c，完整粘贴下面代码；按 Ctrl+O 保存、Enter确认、Ctrl+X 退出。

#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>

typedef uint32_t ULONG;
typedef uint8_t UCHAR;
typedef uint16_t USHORT;

typedef struct {
    ULONG Signature; ULONG TableLength; UCHAR Revision; UCHAR Checksum;
    UCHAR OemId[6]; UCHAR OemTableId[8]; ULONG OemRevision;
    ULONG CreatorId; ULONG CreatorRevision;
} AMD_ACPI_DESCRIPTION_HEADER;

typedef struct {
    AMD_ACPI_DESCRIPTION_HEADER SHeader; UCHAR TableUUID[16];
    ULONG VBIOSImageOffset; ULONG Lib1ImageOffset; ULONG Reserved[4];
} UEFI_ACPI_VFCT;

typedef struct {
    ULONG PCIBus; ULONG PCIDevice; ULONG PCIFunction;
    USHORT VendorID; USHORT DeviceID; USHORT SSVID; USHORT SSID;
    ULONG Revision; ULONG ImageLength;
} VFCT_IMAGE_HEADER;

typedef struct { VFCT_IMAGE_HEADER VbiosHeader; UCHAR VbiosContent[1]; }
GOP_VBIOS_CONTENT;

int main(int argc, char **argv) {
    FILE *fp_vfct, *fp_vbios; UEFI_ACPI_VFCT *pvfct;
    char vbios_name[0x400];
    if (!(fp_vfct=fopen("/sys/firmware/acpi/tables/VFCT","rb"))) {
        perror(argv[0]); return -1;
    }
    if (!(pvfct=malloc(sizeof(UEFI_ACPI_VFCT)))) { perror(argv[0]); return -1; }
    if (sizeof(UEFI_ACPI_VFCT)!=fread(pvfct,1,sizeof(UEFI_ACPI_VFCT),fp_vfct)) {
        fprintf(stderr,"failed to read VFCT header\n"); return -1;
    }
    ULONG offset=pvfct->VBIOSImageOffset, tbl_size=pvfct->SHeader.TableLength;
    if (!(pvfct=realloc(pvfct,tbl_size))) { perror(argv[0]); return -1; }
    if (tbl_size-sizeof(UEFI_ACPI_VFCT)!=
        fread(pvfct+1,1,tbl_size-sizeof(UEFI_ACPI_VFCT),fp_vfct)) {
        fprintf(stderr,"failed to read VFCT body\n"); return -1;
    }
    fclose(fp_vfct);
    while (offset<tbl_size) {
        GOP_VBIOS_CONTENT *vbios=(GOP_VBIOS_CONTENT *)((char *)pvfct+offset);
        VFCT_IMAGE_HEADER *vhdr=&vbios->VbiosHeader;
        if (!vhdr->ImageLength) break;
        snprintf(vbios_name,sizeof(vbios_name),"vbios_%x_%x.bin",
                 vhdr->VendorID,vhdr->DeviceID);
        if (!(fp_vbios=fopen(vbios_name,"wb"))) { perror(argv[0]); return -1; }
        if (vhdr->ImageLength!=fwrite(&vbios->VbiosContent,1,
            vhdr->ImageLength,fp_vbios)) return -1;
        fclose(fp_vbios);
        printf("dump vbios %x:%x to %s\n",vhdr->VendorID,vhdr->DeviceID,vbios_name);
        offset+=sizeof(VFCT_IMAGE_HEADER)+vhdr->ImageLength;
    }
    free(pvfct); return 0;
}

update-initramfs -u -k all

17.2 网络也无法访问时

  1. 在 BIOS/UEFI 启动菜单选择 Proxmox。
  2. 在 GRUB/systemd-boot 菜单临时编辑内核命令行，删除 initcall_blacklist=sysfb_init 和本次增加的 VFIO/IOMMU 参数。
  3. 启动恢复环境，将 vfio.conf 和 pve-blacklist.conf 改名。
  4. 恢复预先备份的 Bootloader 配置。
  5. 更新 initramfs/Bootloader 后重启。
  6. 恢复网络后先执行 qm set 101 --onboot 0。
